# 规则包自己的操作

{pack_ops}

## 现在只做状态转移:这一拍世界从什么变成了什么。分两段输出:
<vars>
登记变量的新值,一行一个「变量名 = 新值」,只写这一拍变了的;变量名只用上面「能改的变量」里的;玩家的位置写 location(换了地方就要写,哪怕叙事只写到那里的人和东西):写叙事最后停住的地方——走在路上、到了门外还没进去,写那条路(「远行」里每条路给了 id),不要写目的地
</vars>
<files>
其余落进文件系统的变化,一行一个,按上面 ops 的写法:
- new / patch / remove:登记类的实例(物品、委托、状态效果、携带物……);接下、完成、放弃的委托,patch 那条委托本身(状态、谁接的)
- new_npc:叙事里新出现的人
- move 谁 去哪:玩家以外的人的去向
- 写下的文字:[~write 路径.md]文字原文[/write](路径只用 .md / .txt / .json);删掉:rm 路径;另有 edit / mkdir / rmdir
- new_location / new_town / link / unlink:只是听说或提到、这一拍没走进去的地方和路——听说了一个地图上没有的地方,就落成地方:别的镇子、村子、港口写 new_town,镇里的地方写 new_location;不要只写进谁的属性里
- define:世界里需要一种还没有的东西(少见)
</files>
叙事里发生了的都要有;工具回包里引擎已经判过的,以回包为准;没发生的不写;东西也要落:谁用掉、吃掉、喂掉、送出、丢下了东西,patch 剩下的数量(一个不剩就 remove),拿到的 new;钱也一样:付出去、收进来的钱写到钱的变量上;给人或动物起了名字,patch 它的名字;玩家和带 (角色) 标记的角色都一样照写(受伤、东西、装备),只是角色的情绪、想法、打算不写。不要再写 <lines> 和 <options>。
身上的后果要落成数,不能只写在叙事里:受伤、中毒、恶心、冻僵、累垮——当场的损失写变量(如 player.hp);会持续的写成状态(词条包列了「状态」这一类时):状态表里有的只写 `new status 名字`,怎么持续、怎么好由表里那一行定;表里没有的写 `new status 名字 note=一行规则`,怎么写都行(如「持续 3 次结算 · 每次结算 player.hp -1 · 敷药可解」)。叙事里状态好了(敷了药、烤了火、睡了一觉)就 remove 它。通缉、嫌疑、声望、知道了什么不是身上的状态,写 flag、变量或关系。检定失败、而事先说好了失败的代价的,这个代价一定要落。
谁的东西写清楚:状态、随身物品这类属于某个人的,名字前写主人——`{{{{<id>}}}}/名字`。`{{{{user}}}}` 是玩家;别人写词条包里他名字前面的 id,用 {{{{ }}}} 括起来;如 `new status {{{{user}}}}/轻伤 note=…`、`remove {{{{<id>}}}}/流血`。地点写完整路径(如 `T001/guild`)。文字里(note、写下的文字)提到人也写 `{{{{id}}}}`,引擎会换回名字。只写名字的算玩家的。
