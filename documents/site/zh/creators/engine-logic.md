## 一句话

> **状态:混合** —— 每一段标了「已实装」(随 1.0 发布)或「设计中」(已定稿、未写代码)。

**你写世界,引擎负责让世界讲道理。** 一个只有设定文本、没有任何规则表的世界,也应该做到:不存在的东西不会凭空出现,钱不会凭空多出来,做过分的事会有人管,角色会按自己的性格拒绝玩家。做不到,是引擎的问题,不是你的提示词不够长。

你写的表、规则和提示词,只用来**改结果**:守卫更弱一点,腹痛改叫「水土不服」,神灯在你的世界里是真的。

## 不用你写的事

| 引擎替你做的事 | 怎么做到的 | 状态 |
|---|---|---|
| 玩家说的话只是尝试 | 每回合先把原话里提到的人、物、地点和世界核对一遍,告诉角色和讲述者哪些在、哪些不在 | 已实装(人物、敌人、地点);凭空的物件(神灯)还有漏网 |
| 角色有自己的主意 | 每个在场角色单独一次调用,拿理解过的场景,自己决定说什么、跟不跟 | 已实装 |
| 不确定的事交给裁判和骰子 | 讲述者写 `[referee …]`,裁判给属性和难度,引擎按人物卡掷骰 | 已实装 |
| 打架有专门的一层 | `[combat 山贼×3]` 切到战斗层,对手按表生成,每轮必须掷骰,hp 写进状态 | 已实装 |
| 地图按真实状态画 | 玩家看地图或问路时引擎直接画,讲述者不用画也不用等 | 已实装 |
| 状态不会被叙事偷改 | 每个改动都过校验:谁在场、变量范围、类允不允许新增 | 已实装 |
| 过分的事有后果 | 行为分类(抢夺、伤害他人、接触有害物……)对应默认后果:敌对、喊人、管事的来、生病 | 设计中 |

## 你可以改的四样东西

1. **表**:`game/rules/<表名>.json` 覆盖引擎自带的表 —— `hazards`(路上的事)、`foes`(对手的数值档)、`rules`(难度档、检定规则)。
2. **提示词**:按「段 · 层 · 槽」覆盖,三层叠加:模板的 `pack.json` < 世界的 `manifest.json` → `prompt` < 游玩中的 `game/meta/prompt.json`。槽有 `rules` · `voice` · `blocks` · `ops_docs` · 条目 `entries`(总是 / 关键词 / 地点 / 变量 / flag 命中时贴进来)。
3. **触发规则**:WHEN → IF → THEN / ELSE,写在世界里,引擎每回合落地后检查,可以级联。
4. **op 与面板**:登记新的动作或工具时声明它等不等回包(`wait`)和怎么显示(文本 / JSON / 图片面板)。

检定怎么算:主持(GM)只选谁检定、对谁、用哪项属性或技能、哪一档难度,**不写数字**;引擎读规则面板、加状态修正、掷骰、判成败。`rpg` 是 1d20 + 修正对 DC;`pct` 是 d100 对目标值(属性 × 5 或技能值),结果分 `crit`(大成功)· `special`(特殊成功)· 成功 · 失败 · `fumble`(大失败)。属性用缩写,如 `str` `dex` `int` `cha`(旧人物卡里的 `app` 读作 `cha`)。规则表、规则面板和档位的完整写法见 [规格](/docs/developers/specs) 里的「规则包 RPG Pack」。

每个世界文件夹里都有引擎生成的 `CONTEXT.md`,列出这个世界的全部 op 和写法,改完设定后重新生成即可。

## 在提示词和样例里怎么写

| 写法 | 意思 |
|---|---|
| `[op 参数]` | 要等结果:骰子、裁判、问某个角色、进战斗 |
| `[~op 参数]` | 不用等:移动、改变量、立 flag、画地图 |
| `<…>` | 引擎说给模型听的(角色台词、已发生的事、请求回包、被拒理由),不要在你的样例里让模型写 |

等不等最终由注册表决定,写错不会出事,但会在日志里记一笔。

## 四个例子,零配置

| 玩家说 | 引擎怎么处理 | 状态 |
|---|---|---|
| 我去旅店要一间房 | 旅店在镇内可达 → 移动;米拉报价;付钱写进钱包 | 已实装 |
| 我捡石头扔守门的老兵 | 讲述者叫裁判 → 掷骰未过 → 石头砸偏,老兵察觉、亮刀 | 已实装 |
| 眼前出现一盏神灯,我许愿一万金币 | 世界里没有神灯 → 什么都没发生;加钱的 op 被拒 | 部分:人物和敌人能拦住,凭空的物件有时漏过(测试里出现过一次真给了钱),在修 |
| 我拔剑逼老苇交钱 | 抢夺 → 对抗检定 → 老苇喊人 → 守卫到场、警戒上升、进战斗层 | 设计中(现在靠讲述者叫裁判和战斗,没有默认后果表) |
