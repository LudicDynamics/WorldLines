## 一句话

**你写世界,引擎负责让世界讲道理。** 一个只有设定文本、没有任何规则表的世界,也应该做到:不存在的东西不会凭空出现,钱不会凭空多出来,做过分的事会有人管,角色会按自己的性格拒绝玩家。做不到,是引擎的问题,不是你的提示词不够长。

你写的表、规则和提示词,只用来**改结果**:守卫更弱一点,腹痛改叫「水土不服」,神灯在你的世界里是真的。

<!-- section: free -->
## 不用你写的事

| 引擎替你做的事 | 怎么做到的 |
|---|---|
| 玩家说的话只是尝试 | 每回合先把原话里提到的人、物、地点和世界核对一遍,告诉角色和讲述者哪些在、哪些不在。人物、敌人、地点核得最稳;凭空冒出来的物件不一定每次都拦得住 |
| 角色有自己的主意 | 每个在场角色单独一次调用,拿理解过的场景,自己决定说什么、跟不跟 |
| 不确定的事交给裁判和骰子 | 讲述者写 `[referee …]`,裁判给属性和难度,引擎按人物卡掷骰 |
| 打架有专门的一层 | `[combat 山贼×3]` 切到战斗层,对手按表生成,每轮必须掷骰,hp 写进状态 |
| 地图按真实状态画 | 玩家看地图或问路时引擎直接画,讲述者不用画也不用等 |
| 状态不会被叙事偷改 | 叙事写完后,另一次调用把这一回合的变化写成状态;每个改动都过校验(谁在场、变量范围、类允不允许新增);和工具、引擎的裁定冲突时,以裁定为准 |
| 状态效果自己会跑 | 「中毒 3 回合、每回合 hp −1」这类效果写成一行,引擎认出倒计时、每回合变化和检定修正,自己计数、自己移除 |

还没有的:按行为分类(抢夺、伤害他人……)自动给出默认后果的表。现在这类事靠讲述者叫裁判、进战斗层。

## 一回合分几拍

从 PyPI 装的 WorldLines 自带完整的两拍编排:先**商量**(主持接住你的话、在场角色表态,世界不动),谈妥了再**清算**(真的发生、写进状态)。从开源仓库源码装的引擎只跑单拍,每回合直接清算。两个内置模板都用两拍。详见[一回合怎么走](/docs/concepts/turn-flow) 和[商量与清算](/docs/concepts/planning-resolve)。

## 你可以改的四样东西

1. **表**:`game/rules/<表名>.json` 覆盖引擎自带的表 —— `hazards`(路上的事)、`foes`(对手的数值档)、`rules`(难度档、检定规则)。状态效果写在 `game/rules/status.md`,一行一个。
2. **提示词**:按「段 · 层 · 槽」覆盖。运行时三层叠加:规则包自带 < 世界的 `manifest.json` → `prompt` < 这一局的 `game/meta/prompt.json`。开局时模板的 `prompts/` 和剧情包的 `prompt` 会合进 `game/meta/prompt.json`;模板写了 `world.prompts: "replace"` 时,世界自带的那份不要,只用模板的。槽有 `rules` · `voice` · `blocks` · `ops_docs` · 条目 `entries`(总是 / 关键词 / 地点 / 变量 / flag 命中时贴进来)。
3. **触发规则**:WHEN → IF → THEN / ELSE,写在世界或剧情包里,引擎每回合落地后检查,可以级联。见[触发规则](/docs/creators/triggers)。
4. **op 与面板**:登记新的动作或工具时声明它等不等回包(`wait`)和怎么显示(文本 / JSON / 图片面板)。

检定怎么算:主持只选谁检定、对谁、用哪项属性或技能、哪一档难度,**不写数字**;引擎读规则面板、加状态修正、掷骰、判成败。`rpg` 是 1d20 + 修正对 DC;`pct` 是 d100 对目标值(属性 × 5 或技能值),结果分 `crit`(大成功)· `special`(特殊成功)· 成功 · 失败 · `fumble`(大失败)。属性用缩写,如 `str` `dex` `int` `cha`(旧人物卡里的 `app` 读作 `cha`)。规则表、规则面板和档位的完整写法见 [规格](/docs/developers/specs) 里的「规则包 RPG Pack」。

每个世界文件夹里都有引擎生成的 `CONTEXT.md`,列出这个世界的全部 op 和写法,改完设定后重新生成即可。

## 在提示词和样例里怎么写

| 写法 | 意思 |
|---|---|
| `[op 参数]` | 要等结果:骰子、裁判、问某个角色、进战斗;也可以请引擎裁定一个改动,如 `[move player 北门]`、`[player.gold -12]`,引擎当场回答,叙事接着写 |
| `[~op 参数]` | 不用等的工具:地图、人物卡这类面板,落地后再画 |
| `<…>` | 引擎说给模型听的(角色台词、已发生的事、请求回包、被拒理由),不要在你的样例里让模型写 |

移动、改变量、立 flag 这些**状态变化**不用写成 `[~op]`:叙事写完后,写状态那一步会把它们读出来。等不等最终由注册表决定,写错不会出事,但会在日志里记一笔。

## 四个例子,零配置

| 玩家说 | 引擎怎么处理 |
|---|---|
| 我去旅店要一间房 | 旅店在镇内可达 → 移动;米拉报价;付的钱写进钱包 |
| 我捡石头扔守门的老兵 | 讲述者叫裁判 → 掷骰未过 → 石头砸偏,老兵察觉、亮刀 |
| 眼前出现一盏神灯,我许愿一万金币 | 世界里没有神灯 → 什么都没发生;加钱的改动被拒。凭空的物件偶尔会漏过 |
| 我拔剑逼老苇交钱 | 讲述者叫裁判做对抗检定,失败或闹大了进战斗层;没有现成的「抢夺 → 喊人 → 守卫到场」默认后果表 |
