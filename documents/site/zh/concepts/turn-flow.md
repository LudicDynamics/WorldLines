## 先说结论

> 回合外面还有一层:先由世界主持**商量**、谈定了再**清算**,见 [商量与清算](/docs/concepts/planning-resolve)(已实装,默认关闭)。这一页讲的是清算这一拍里引擎怎么走。
>
> **10-04 变更(设计已定 · 实装中):** ④ 讲述不再一次写出 lines · ops · options。改成 ④ 只写叙事(要结果的事在叙事里调工具)→ ④b 用一个干净的上下文统一出状态转移(`<vars>` 登记变量新值 · `<files>` 文件系统变化)→ ⑤ 对账。选项改成工具。

> **状态:混合** —— 每一段标了「已实装」(开发分支跑通、有测试、未发布)或「设计中」(已定稿、未写代码)。

一回合分六段:**规划 → 角色 → 结算 → 讲述 → 校验 → 落地**。只有「讲述」是一次厚的 LLM 调用;规划用一次很便宜的选择题(Jev);校验和落地是纯引擎代码。

三条原则贯穿全部六段:

1. **玩家、角色、世界三方各有主体性,互相隔离。** 角色拿到的是引擎理解过的场景,不是玩家的原话;世界自己决定后果。
2. **玩家的话是一次尝试,不是事实。** 「眼前出现一盏神灯」只是玩家想这样,世界里有没有,由引擎查。任何一方(包括玩家)的行动都可能被否决。
3. **效果靠机制,不靠长提示词。** 零配置、一句基础提示,也要做到抢劫被围、乱吃东西生病;创作者的表和规则只用来**改**结果,不是用来**补**能力。

<!-- section: stages -->
## 六段

```text
玩家一句话(= 尝试)
  ① 规划 PLAN     定位指代 · 一次 Jev 选择题 · 入口规则 · 选层 · 给每个角色装视角包
  ② 角色 SOULS    在场角色并行:台词 + 意图 + 判断
  ③ 结算 RESOLVE  玩家和角色的行动同桌结算,任何一方可被否决;默认后果
  ④ 讲述 SOLVE    厚调用:按结算事实只写叙事(可流式)
                  [请求] 停下 → 引擎执行 → 回包 → 续写    [~动作] 不等(④ 之后再执行)
  ④b 状态转移     一次调用,干净的上下文(全部叙事 + 全部工具结果 + 登记表):
                  <vars> 登记变量新值 · <files> 文件系统变化
  ⑤ 校验 VALIDATE ④b 对 ④ 里改世界的工具对账(冲突:有 Jev 用 Jev,没有听工具)· 用完整注册表查每个 op;
                  不过就带理由只退回 ④b,叙事不改
  ⑥ 落地 APPLY    写进世界 → 触发规则 → 层的每回合结算 → 面板
```

| 段 | 谁来做 | 状态 | 通常耗时 |
|---|---|---|---|
| ① 规划 | 引擎 + Jev | 部分实装:指代定位、Jev 预判、入口规则、选层已跑;合成一个 Plan 对象、一次 Jev 出全部判断、视角包在设计中 | 约 0.3 s |
| ② 角色 | 每个在场角色一次 LLM,并行 | 已实装 | 约 2 s |
| ③ 结算 | 引擎,有争议时叫裁判 | 设计中。现在由讲述者写 `[referee …]` / `[dice …]` 请求,引擎裁定后再续写 | 无冲突 0 s |
| ④ 讲述 | 一次 LLM(请求会让它续写) | 已实装(现行版本仍一次写 lines · ops · options;只写叙事的版本实装中) | 约 4–9 s |
| ④b 状态转移 | 一次 LLM,前缀与 ④ 相同(吃缓存) | 设计已定 · 实装中 | 约 3 s |
| ⑤ 校验 | 引擎 | 已实装 | 毫秒级 |
| ⑥ 落地 | 引擎 | 已实装;通用「状态效果」(中毒、腹痛、通缉)在设计中 | 毫秒级 |

## 每一步的输入、输出、格式

下面用一个真实回合走一遍(石津北门,玩家旅人,艾琳娜同行)。玩家说:

```text
我捡起一块石头朝守门的老兵扔过去,看他什么反应。
```

**① 规划 · 指代定位**(引擎,已实装)。输入:原话 + 世界索引。输出:每个被提到的东西在不在这里,写成一段给角色和讲述者看的「理解」:

```text
# 本回合的理解(引擎,按世界的事实)
玩家试图:我捡起一块石头朝守门的老兵扔过去(这是尝试,结果还没定)
- 守门的老兵:就在这里
```

不存在的东西会写成「此处没有(原因)。不要让它凭空出现」。

**① 规划 · Jev 预判**(Jev,已实装)。输入:原话 + 场景。输出:意图、紧张度、每个角色要不要反应、反应多深(形状如下,数字取自一次真实运行):

```json
{"source": "jev", "intent": {"kind": "move", "confidence": 0.99}, "tension": 0.653,
 "souls": {"si-elena0001": {"present": true, "reacts": 0.72, "depth": "speak"},
           "si-rowan0001": {"present": false, "reacts": 0.0, "depth": "silent"}}, "ms": 306}
```

**① 规划 · 入口规则**(引擎,已实装)。在讲述者动笔前就定下来的事:路上有拦路的事而玩家动手 → 这回合直接进战斗层;玩家看地图或问路 → 引擎直接画一张地图给玩家(异步,不问讲述者)。

**② 角色**(LLM,已实装)。输入:她自己的人设和记忆 + 上面那段「理解」(不是玩家原话)。输出:她的台词、动作、意图:

```text
<say 艾琳娜 attitude=oppose>「你要是想跟守门人搭话,用嘴。要是想挨揍,别拉上我。」</say>
```

**④ 讲述**(LLM,已实装)。输入:执行包(这一刻相关的条目)+ 角色回包 + 玩家原话。输出分三块:`lines` 是玩家看到的叙事,`ops` 是状态改动,`options` 是给玩家的选项。讲述者觉得扔石头的后果不该自己定,就在 ops 里写了一个**同步请求**(节选,分节用默认的 XML 写法):

```text
<lines>
你蹲下去,从路沿的石缝里抠出一块湿石头。
石头还没出手,艾琳娜一把攥住你的手腕。
「你要是想跟守门人搭话,用嘴。要是想挨揍,别拉上我。」
</lines>
<ops>
[referee 玩家朝守门老兵扔石头:有没有真出手、老兵有没有察觉、会不会当场起冲突]
</ops>
<options>
松开石头,改口问北墙外的事
「你松手。」
</options>
```

方括号的请求就是停点:写到这里停,引擎先执行。

**引擎执行请求**(引擎 + 裁判子调用,已实装)。裁判只给结构化裁定(用哪个属性、难度档、情境修正),骰子由引擎按人物卡和难度表掷。回包用尖括号送回讲述者:

```text
# 工具回包(你上一次写的请求,引擎已执行;从请求那一行接着续写)
<referee 玩家朝守门老兵扔石头…>裁定:allowed_with_consequences;检定 投掷(手法) d20 + DEX -1:3+1=4 vs DC 12 → 未过;结果:出手却出了动静,老兵顺着声音朝你这边看过来,当场对峙。</referee>
```

**④ 讲述 · 续写**。已经显示给玩家的部分定稿,从停点往下写:

```text
<lines>
石头低了半尺,脱手,砸在门柱上。
老兵回过头。他把斗篷往后一撩,露出腰上一柄短刀。
「我在这门口站了十二年,没见过谁手滑能滑出这么大动静。」
</lines>
<ops>
new_npc 守门老兵 T001/gate_north 守门人
</ops>
```

**⑤ 校验**(引擎,已实装)。输入:ops + 完整注册表。查 schema、范围、谁在场、类的增长策略、层的依据(比如进战斗得有可打的人)。不通过就带理由退回给讲述者重写:

```text
<refused combat roster>这里没有可打的对象:路上没有停点,这里也没有遭遇</refused>
```

**⑥ 落地**(引擎,已实装)。通过的 ops 写进世界文件夹 → 触发规则(if / then,可级联)→ 当前层的每回合结算(战斗:下一轮)→ 面板(地图、阵型)→ 记下这一回合所有调用的 request id。输出:新状态 + 画面。

## 括号约定:形状就是等不等

> **状态:已实装 · 尚未发布**(10-01 定稿)

| 写法 | 意思 | 例子 |
|---|---|---|
| `[op 参数]` | **同步请求**:写到这一行就停,引擎回包后续写 | `[dice 1d20+2 vs 12]理由[/dice]` · `[referee 玩家想做的事]` · `[ask 艾琳娜]` · `[combat 山贼×3]交接[/combat]` |
| `[~op 参数]` | **异步动作**:不等回包,引擎照做,接着写 | `[~map]` · `[~sheet]`(只给玩家看的,在落库之后画) |
| `<…>` | **引擎发给模型的消息**,模型不写 | `<say>` 角色的话 · `<event>` 已发生的事 · `<referee>…</referee>` 回包 · `<refused>` 被拒理由 |

**等不等由引擎决定,不由括号决定。** 每个 op 注册时声明 `wait`;模型括号写错时按注册表执行,不一致记进 trace。实测两种异步写法(`<map>` 与 `[~map]`)标错率都是 0,定为 `[~ ]` 是为了只用一种括号。

输出的分节标记固定用 XML。分割线和代码围栏都测过,不采用。现行版本是 `<lines>` `<ops>` `<options>`;10-04 起讲述只有 `<lines>`,状态转移是 `<vars>` `<files>`,选项是 `[options …]` 工具。

<!-- section: retry -->
## 被拒了怎么办

- **已实装**:被拒的 op 带理由退回,讲述者只改那一处重写(有次数上限);通过的部分照常落地,不通过的丢掉;停点之前已经显示的文字定稿,续写只往后加。
- **设计中**:四级重来(定点重写 → 部分接受 → 从停点重来 → 整回合重来);次数用完时只落通过的,正文换成一句「世界的抵抗」,不卡住回合。
