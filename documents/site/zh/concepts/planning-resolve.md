## 先说结论

> **状态:商量已实装 · 清算的「先叙事后状态转移」设计已定、实装中 · 均未发布** —— 在 NeonRP 开发分支,有测试和基准;**默认关闭**,在 `engine.json` 里打开 `turn.plan_loop`。一拍之内引擎怎么走见 [一回合怎么走](/docs/concepts/turn-flow),这一页讲它外面一层。

一回合分两种拍,**各是一个 agent loop**:

- **商量拍(Planning)只负责「看」。** 世界当主持(GM):把玩家的意图放进场景,决定问谁,摆出代价、检定和要花的时间,维护一块**计划板**。只能读、不能写,世界一个字都不变。
- **清算拍(Resolve)负责「做」。** 同一个世界(主持和 world agent 是同一个人)按谈定的计划写出这一拍:先写叙事——要结果的事在叙事里调工具;叙事写完,再用一个干净的上下文统一出一次**状态转移**,对账、落库。

商量的内容就是清算的输入——商量的目的就是把要做的事谈清楚。清算拍里没有玩家或角色的轮次,也没有选项回合。

## 总图

```text
 开始游戏 ──→ 【开场】世界自己写好的开场(game-start.json),不调模型
                │
 玩家一句 ──→ 【商量拍 · agent loop】 世界当主持,一轮一轮:想 → 调工具 → 看结果 → 再想
                │   工具:[read 名字] 读真实记录 · <mic> 把话筒递给在场角色 · <board> 改计划板、约检定
                │   这一拍怎么结束(由 loop 自己决定):
                │     · 把话交回玩家(1–3 句,真有分歧才给选项)→ 等玩家
                │     · next: advance → 切清算
                │   打断:玩家 @主持 · 角色 @主持 · Jev(或小模型)判定已谈定
                │   切之前:有不确定 / 有对抗的事还没约检定 → 再补一轮约上
                ▼ 商量拍单独记一条
 【清算拍 · agent loop】(接着跑,不等玩家开口)
   ① 叙事:只写叙事,结果会决定后文的事在那一行调工具,写到这里停、拿到结果接着写
          [dice] [roll] [referee] · [ask 名字](请角色执行她谈定的事)· [move 远处] · [new_location] · [new_town]
          · [link] [unlink] · [pay] · [combat](这一拍在战斗层的提示下接着写)· [options] · [~map] [~sheet]
   ② 状态转移:一个干净的上下文(这一拍全部叙事 + 全部工具结果 + 登记表与开始时的值)
          <vars>  闭 schema:登记变量的新值 → run_state 等状态文件
          <files> 开 schema:文件系统的变化(实例、文字、新出现的人和地方)
   ③ 对账:② 对 ① 里改世界的工具;冲突有 Jev 用 Jev,没有就听工具结果 · verify · 叙事里没发生的丢
          要补只重跑 ②,叙事一个字不改
   ④ 落库 → 画地图 → 回合后(每个人的经历、地点补位)
                ▼ 清算拍单独记一条
               回到商量
```

## 商量拍

1. **它是 agent loop,不是固定流程。** 主持每一轮自己决定:要不要查资料(`[read 杂货铺]`,读到的只有它知道)、要不要把话筒递给谁(`<mic>`)、计划板怎么改(`<board>`)。工具结果回来再想下一轮;没有工具调用的那一轮就是最后一轮。一拍最多 4 轮(`turn.plan_loop_max_rounds`)。
2. **对玩家只说 1–3 句。** 信息、代价、风险、要问谁;不写环境和动作描写——画面留给清算。NPC 的话主持可以直接代说。开场例外:开场是世界自己写好的。
3. **递话筒。** 主持用主持的口吻把玩家的话转述给她、问她怎么看,不替她说话;她自己回(说出口的话 + 这一拍的打算),结果回到主持。玩家写 `@艾琳娜`、直接点她的名字、或者「让她去……」,她在第一轮就拿到话筒。
4. **检定只约不掷。** 写成 `检定: 谁 属性 难度 为了什么` 或 `对抗: 甲 vs 乙 属性 为了什么`,存进计划板;清算时引擎按人物卡掷。
5. **商量时世界不动。** 时钟不走、文件不改;谈话、计划板、约好的检定只在场景缓冲 `.neonrp/scene.json` 里。谈话本身也算时间,清算时计入。
6. **玩家的话是尝试。** 闸门把玩家替世界说了算的话(「天已经黑了」「他答应了」)标成他的说法,不是事实;点到的名字有出处才落地,无中生有的不造。

## 怎么从商量进到清算

| 谁 | 怎么 | 发生什么 |
|---|---|---|
| 商量 loop 自己 | 该谁做什么都清楚、没人反对 → `next: advance` | 一句复述谈定的事(不给选项、不问「就这么定?」),切清算 |
| Jev / 小模型 | 主持把话交回玩家后,判定其实已经谈定 | 去掉选项,切清算 |
| 玩家 | `@主持`(`@GM` `@世界` `@world` `@dm` 同效) | **不是 100% 推进**:主持果断接这一轮,不再问别人,自己定——能做就切,不能就点出那一件没定的事。推进的只是玩家自己那部分,别人没点头不挡他 |
| 角色 | 她在回话里 `@主持` | 下一轮是主持果断的一轮,同上(只推她自己的部分) |
| 玩家 | 说「定」 | 按计划板切 |
| 外部事件 | 战斗进行中、路上的停点未了结 | 不等商量,直接清算 |

**聊得久不会被切断。** 第 3 拍起(`turn.plan_loop_nudge_at`)主持会劝一劝——复述谈定的、建议动手——但不强推;切不切还是上面这几种。

## 清算拍

- **叙事里的工具 = 结果决定后文的事。** 掷骰、请角色执行、去远处(可能被截在城门)、走进一个地图上没有的地方、去一个新城镇、走新路或路断了、钱可能不够、打起来了——叙事写到这里停,引擎给结果,接着写。其余已经写进叙事的后果(花了钱、给出收下、写下的字、别人去哪、新出现的人)不用边写边记,交给 ②。每个 op 落在哪一边见 [提出 → 校验 → 落地](/docs/concepts/ops)。
- **角色在清算里是执行,不是又一轮商量。** 叙事需要她出场时调 `[ask 她]`,问法是:你谈定的打算是什么、跟你有关的骰子掷出了什么、现在场上是这样——照计划去做、去说,意外可以临场应变,不改计划、不开新话题。同一次清算里每人最多两次。
- **骰子先掷、写进叙事前面。** 谈定的检定在清算开始时就按人物卡掷好,清算开头一行显示:`[艾琳娜 CHA(压药价): 13+2=15 >= 12] → 成功`;成没成,叙事必须跟它一致。
- **状态转移分两段,对应两类 schema。** `<vars>` 写登记变量的新值(时间、位置、钱、hp、flag);`<files>` 写文件系统的变化(登记类的实例、文字、新地点、新人物)。角色自己的状态和日记世界不写,由她自己结算。
- **选项是工具。** 想把选择交给玩家就调 `[options …]`,不调就没有;引擎和前端也能自己调。
