<!-- section: loop -->
## 一个回合

> **状态:随 1.0 发布**

```text
提出(玩家一句话 / 主角的判断 / 规则 / hook / 导演)
   → world agent 写叙事(要结果的事在叙事里调工具)
   → 统一出一次状态转移:<vars> 登记变量新值 · <files> 文件系统变化
   → 对账 + verify(查 schema、范围、谁在场、类的策略)
   → apply(写进世界文件夹)
   → 事件记进账本 → 订阅者、触发规则、界面
```

> 10-04 起(设计已定 · 实装中)叙述者不再边写叙事边列 ops。现行版本仍是一次调用里同时写 `<lines>` 和 `<ops>`。

<!-- section: routing -->
## 每个 op 落在哪一边

同一个 op 可能落在两边。判据不是 op 本身,而是**这一拍的叙事要不要等它的结果才写得下去**——要等,就是叙事里的工具;不用等,就是叙事写完后统一出的状态转移。

| 去处 | op | 为什么 |
|---|---|---|
| **叙事里的工具**(写到这里停,拿到结果接着写) | `dice` · `roll` · `referee` | 成没成由骰子、裁判定 |
| | `need`(`[ask 名字]`) | 她怎么说怎么做由她定 |
| | `combat` / `end_combat` | 切层:后文换一套写法 |
| | `new_town` | 引擎定路程和从哪个镇修路,叙事按路程写 |
| | `new_location`(这一拍就要走进去) | 引擎判画不画得进地图、挂在哪 |
| | `move_to` 玩家远行 | 引擎判到得了,还是被截在城门 |
| | `link` / `unlink`(这一拍要走这条路 / 路断挡道) | 断了会让镇上有地方走不到时引擎拒 |
| | `pay`(钱可能不够) | 不够就买不成 |
| | `[~map]` · `[~sheet]` | 只给玩家看,不等;落库后再画 |
| | `options` | 把选择交给玩家;不调就没有 |
| **状态转移 · `<vars>`**(闭 schema:写新值) | `set` · `add` · `flag` | 时间、位置(镇内)、钱、hp、警戒、声望、flag |
| **状态转移 · `<files>`**(开 schema:文件系统) | `new` · `patch` · `remove` | 登记类的实例:物品、委托、状态效果、携带物 |
| | `new_npc` · `move_to` 玩家以外的人 | 新出现的人、别人的去向 |
| | `write` · `rm` · `edit` · `mkdir` · `rmdir` | 写下、改动、删掉的文字和文件 |
| | `new_location` / `new_town` / `link` / `unlink`(只是听说、提到) | 这一拍没走进去,没有叙事等它的结果 |
| | `define` | 世界需要一种还没有的东西(少见,单独校验) |
| **都不出** | `engage` · `mood` | 前者已退役;后者只给角色自己用,世界不写角色 |

<!-- section: refusal -->
## 拒绝

verify 不通过时返回**可读的理由**,叙事据此改写,而不是静默失败:

```json
[{"op": "move_to", "who": "player", "to": "T004/tavern"},   // ✓
 {"op": "need", "who": "rowan"}]                            // ✗ 罗文不在这里 —— 只能问在场的人
```

`add` 超出范围会被钳位;只读变量只有引擎能写;关掉一个 op 就是把它从 `actions` 表里拿掉。

<!-- section: hooks -->
## 订阅也只能提出

订阅者(hook)在事件落地之后被调用,但它**不能直接写文件**,只能把一个 op 排进队列,下一回合照样过 verify。这样引擎之外的逻辑也改变不了「只有 world agent 能改世界」这件事。

<!-- section: tiers -->
## 谁花 token

在你身边的主角用 LLM 说话(T0);不在身边的只做判断(T1,不调 LLM);经济、势力这样的规则是 T2,不花 token。三者的提出走同一条 verify。
