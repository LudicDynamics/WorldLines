## このページについて

このページは実際の順番どおりに進みます。インストールして、モデルをつなぎ、世界を選び、最初のひとことを言い、セーブするところまで遊びます。そのあと自分で世界を作って公開します。各ステップでは**何が起きて、何が見えるか**だけを書きます。詳しいことはそれぞれのページへリンクしています。

先に三つだけ覚えてください。このあとのステップはすべてこの上に成り立っています。

1. **世界・キャラクター・プレイヤーは三者です。** 世界(進行役)が結果を決めます。キャラクターは自分の記憶と意図を持っています。プレイヤーの言葉は**一度の試み**で、事実ではありません。
2. **世界はテンプレート単位で作ります。** テンプレート = 世界 + キャラクターへのリンク + ルールパック + プレイ契約 + 編成。遊ぶ一局はすべてテンプレートから始まります。
3. **ターンごとに「世界コミット」が一つ残ります。** 状態はすべてファイルにあり、1 ターンに 1 コミットです。巻き戻しとは、あるコミットから別の線を始めることです。

<!-- section: editions -->
## 二つのエンジン:完全版とオープンソース版

| | 入れ方 | 1 ターン |
|---|---|---|
| **完全版** | `pip install worldlines` / `pip install neonrp`(PyPI) | 二拍:まず**相談**、次に**解決** |
| **オープンソース版** | [GitHub リポジトリ](https://github.com/LudicDynamics/WorldLines) からソースでインストール | 解決の拍だけ |

どちらも同じテンプレート、セーブ、ルールを読みます。テンプレートが二拍を指定していても、オープンソース版で動かすとエンジンは一拍に戻ります。キャラクターはいつもどおり動きます。以下は完全版で説明します。

<!-- section: install -->
## 1. インストールと起動

- `worldlines`:ローカルの Web ページ `http://127.0.0.1:8787/local` を開きます(ローカル Hub、プレイ画面、ワークベンチ)。
- `neonrp`:ターミナルでランチャーを開きます。世界選び、開始、プレイまで、すべてターミナルで完結します。
- 二つのコマンドは `~/.worldlines`(テンプレート、キャラクターライブラリ、セーブ)を共有します。Web で始めた一局はターミナルでも続けられます。
- 起動時に新しいバージョンを確認し、既定では自動で更新して再起動します。先に確認したいときは `/update mode prompt`。
- インストールしたくない場合は [worldlines.gg](https://worldlines.gg) か iOS アプリでそのまま遊べます。

ローカルには二つの世界が入っています。**グレイオーク館 · 閉ざされた扉**(一夜の推理。はじめての一局向け)と **ストーンフォード · 霧の退く夜**(開かれた町)です。ほかの公式世界はログインしなくてもローカル Hub で見られ、ログインすると手元にダウンロードできます。

<!-- section: model -->
## 2. モデルをつなぐ

- **Worldlines アカウント**:ターミナルでは `/login`、Web ではログインボタン。ログインすると私たちが中継するモデルが使え、判定役 **Jev** もオンになります。
- **自分のキー**:OpenCode、DeepSeek、OpenRouter、Anthropic、OpenAI、GLM、または OpenAI 互換のエンドポイント。
- 新しい一局は前に選んだモデルを使います。選んだことがなくログイン済みなら Worldlines を、そうでなければキーのある最初のものを使います。

**判定役**が答えるのは小さなはい/いいえの問いだけです。たとえば「この相談はまとまったか」「この名前は誰のことか」。Jev がいないときは、**その一局自身のモデル**が答えます(1 拍につき数秒増えます)。それもなければ決まったルールで判定します。判定役が物語を書くことはありません。

詳しくは [モデルプロバイダーの設定](/docs/players/providers) を参照してください。

<!-- section: start -->
## 3. 一局を始める

テンプレートを選び、(任意で)自分のキャラクターを作り、開始を押します。このときエンジンは次のことをします。

1. `~/.worldlines/plays/` の下に新しいフォルダを作ります。この一局のものはすべてここに入ります。
2. テンプレートの世界、選んだ言語層、ルールパックをコピーします。
3. **キャラクターはここで初めて実体化します。** テンプレートのキャラクターの多くはキャラクターライブラリへのリンクです。開始時に初めてこの一局のキャラクターとしてコピーされ、自分の記憶を持ちます。同じキャラクターが複数の世界に同時にいても、互いに影響しません。
4. 設定をまとめます:ルールパック < プレイ契約 < 編成 < 世界 < この一局。後ろのものが前のものを上書きします。
5. オープニングを流し(オープニング画像があれば先に表示)、進行役が作者の決めた最初の場面を書きます。

<!-- section: turn -->
## 4. 1 ターン:まず相談、次に解決

あなたが何か言うと、ターンが始まります。

**相談の拍。** 進行役はあなたの言葉を場面に置き、その場にいるキャラクターにマイクを渡します。キャラクターは返事をし、条件を出し、駆け引きをします。進行役は、それにかかるお金、必要な判定、かかる時間を並べます。**この拍のあいだ世界は動きません**。時計は止まったまま、何も変わりません。話を続けても、考えを変えてもかまいません。

相談から解決に移るのは次のときです。

- 判定役が「まとまった」と判断したとき(Jev がいなければこの一局のモデルが判断);
- あなたがはっきり「決まり」「それで行こう」と言ったとき;
- 相談することのない言葉(町の中を少し歩く、など)はそのまま解決へ;
- 外の出来事は相談が終わるのを待ちません。

`@dm` で進行役に思い切って一手進めてもらえます。`@名前` でそのキャラクターにマイクを渡します。

**解決の拍。** 相談で決まったことが実際に起きます。

1. **誰が動くか。** 判定役があなたのやりたいことと、一緒に動くキャラクターを読み取ります。その場のキャラクターはそれぞれ自分の行動を決め、その場にいないキャラクターも別の場所で一歩進みます。
2. **まずルールで判定。** ダイスが必要なら振り、戦闘などのルール層が必要なら入ります。
3. **地の文を書く。** 進行役がこの拍の本文を書きます。結果があとの展開に関わることは、本文の中でツールを一度呼び、エンジンがその場で裁定を出し、進行役はその裁定どおりに書き進めます。相談で決まった支払いは、エンジンが財布から直接精算します。
4. **状態を書く。** 別のまっさらな呼び出しが本文を読み、変化を書き出します。登録された数値(お金、体力、時間……)と、世界の中のファイル(誰がどこへ行ったか、何を手に入れたか)です。
5. **検査。** エンジンが層ごとに確かめます。書式は正しいか、名前や変数は存在するか、世界のルールが許すか。だめなら状態だけを書き直させ、本文はそのままです。
6. **確定。** 変更をファイルに書き込み、ターン数を 1 つ進め、このターンの世界コミットを作ります。

**状態はまず速く、あとで正確に。** 手順 4 はまず速い方法で確定するので、すぐに続きを遊べます。同時に、考える遅い版がバックグラウンドでこの拍を読み直し、数秒後に間違った値を直します(待つのは最大 90 秒)。画面には「再確認中」と出て、そのあと「修正した内容」か「変更なし」が出ます。先に次のひとことを送ると、再確認は取り消されます。

<!-- section: save -->
## 5. セーブ、巻き戻し、リプレイ

- 一局は一つのフォルダで、1 ターンに 1 コミットです。Web ではコミットグラフが見られます。
- **巻き戻しは何も消しません**:あるターンに戻ると、そこから別の線が始まり、元の線も残ります。ターミナルでは `/undo list` で一覧、`/undo <ターン>` で戻ります。
- `/save`、`/load` でセーブとロード。`/open` で続きから、または新しい一局を始めます。
- エンディングで(または手動で)**リプレイ**として書き出せます。物語、タイムライン、カバーをまとめて、ほかの人に見せられます。

詳しくは [セーブ](/docs/players/saves) を参照してください。

<!-- section: create -->
## 6. 自分の世界を作る

道は三つあります。どれも同じテンプレートフォルダを編集します。

- **Web の創作デスク / iOS**:公式テンプレートから始め、キャラクター、シナリオ、エンディング、手がかりを足し、4 言語のタイトルと紹介文を書き、カバーを替えます。編成は 2〜3 種のプリセットから選ぶだけで、図は読み取り専用です。
- **ローカルのワークベンチ**:「＋ 新しいテンプレート / 世界 / キャラクター」。編成グラフ、地図、トリガーを編集でき、変更はテンプレートに書き戻されます。
- **coding agent**:Claude Code や Codex でテンプレートフォルダを開きます。どのテンプレートにも `AGENTS.md`、`CLAUDE.md`、`spec/` が入っています。仕様どおりにフォルダと JSON / Markdown を書けばよく、エンジンを変える必要はありません。

キャラクターはキャラクターライブラリ(`~/.worldlines/souls/`)に置き、テンプレートにはリンクだけを書きます。

詳しくは [クリエイター クイックスタート](/docs/creators/quickstart) を参照してください。

<!-- section: lint -->
## 7. チェック(lint)

`neonrp template lint <テンプレート>` またはワークベンチのチェックは、まずテンプレートを一局として一時フォルダに開き、それから参照、キャラクター、シナリオ、素材、プレイ契約、4 言語を調べます。結果は二段階です。**block** は公開を止め、**warn** は注意だけです。

<!-- section: publish -->
## 8. Hub に公開する

| | 公開のしかた | 見られる人 |
|---|---|---|
| **フリーエリア** | ローカルの創作デスクから直接アップロード。自動チェックを通ればすぐ公開 | 全員。管理はあとから |
| **デフォルトエリア** | Web / iOS の創作デスクから提出し、審査へ | 審査を通ると掲載 |

アップロード前の関門は三つです。パッケージに鍵や認証情報のファイルがないこと。lint に block がないこと。4 言語のタイトルと紹介文、カバーがそろっていること。同じ作品をもう一度提出すると新しい版になります。審査中に再提出すると、待っていた版と入れ替わります。掲載中の作品を改版した場合、新しい版が審査を通るまでは古い版が公開されたままです。
