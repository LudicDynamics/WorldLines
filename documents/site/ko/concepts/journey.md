## 이 페이지에서 다루는 것

이 페이지는 실제 순서대로 한 번 따라갑니다. 설치하고, 모델을 연결하고, 세계를 고르고, 첫마디를 하고, 저장할 때까지 플레이합니다. 그다음 직접 세계를 만들어 공개합니다. 각 단계에서는 **무슨 일이 일어나고 무엇이 보이는지**만 다룹니다. 자세한 내용은 각 페이지로 연결됩니다.

먼저 세 가지만 기억하세요. 이후의 모든 단계는 이 위에 서 있습니다.

1. **세계, 캐릭터, 플레이어는 세 주체입니다.** 세계(진행자)가 결과를 정합니다. 캐릭터는 자기 기억과 의도를 가집니다. 플레이어의 말은 **한 번의 시도**이지 사실이 아닙니다.
2. **세계는 템플릿 단위로 만듭니다.** 템플릿 = 세계 + 캐릭터 링크 + 규칙 팩 + 플레이 계약 + 편성. 플레이하는 모든 판은 템플릿에서 시작합니다.
3. **턴마다 「세계 커밋」이 하나 남습니다.** 상태는 모두 파일에 있고, 한 턴에 커밋 하나입니다. 되돌리기는 어떤 커밋에서 새 줄기를 여는 것입니다.

<!-- section: editions -->
## 두 가지 엔진: 정식판과 오픈소스판

| | 설치 방법 | 한 턴 |
|---|---|---|
| **정식판** | `pip install worldlines` / `pip install neonrp`(PyPI) | 두 박자: 먼저 **상의**, 다음에 **해결** |
| **오픈소스판** | [GitHub 저장소](https://github.com/LudicDynamics/WorldLines)에서 소스로 설치 | 해결 박자만 |

둘 다 같은 템플릿, 저장, 규칙을 읽습니다. 템플릿이 두 박자를 지정해도 오픈소스판으로 돌리면 엔진은 한 박자로 돌아갑니다. 캐릭터는 평소대로 움직입니다. 아래는 정식판 기준으로 설명합니다.

<!-- section: install -->
## 1. 설치와 실행

- `worldlines`: 로컬 웹 페이지 `http://127.0.0.1:8787/local`을 엽니다(로컬 Hub, 플레이 화면, 워크벤치).
- `neonrp`: 터미널에서 런처를 엽니다. 세계 고르기, 시작, 플레이까지 모두 터미널에서 합니다.
- 두 명령은 `~/.worldlines`(템플릿, 캐릭터 라이브러리, 저장)를 함께 씁니다. 웹에서 시작한 판을 터미널에서 이어서 할 수 있습니다.
- 실행할 때 새 버전을 확인하고, 기본으로 자동 업데이트 후 다시 시작합니다. 먼저 묻게 하려면 `/update mode prompt`.
- 설치하고 싶지 않다면 [worldlines.gg](https://worldlines.gg)나 iOS 앱에서 바로 플레이하세요.

로컬에는 세계 두 개가 들어 있습니다. **그레이오크 저택 · 닫힌 문**(하룻밤 추리, 처음 플레이하기 좋음)과 **스톤포드 · 안개가 물러나는 밤**(열린 마을)입니다. 다른 공식 세계는 로그인하지 않아도 로컬 Hub에서 볼 수 있고, 로그인하면 내 컴퓨터로 내려받을 수 있습니다.

<!-- section: model -->
## 2. 모델 연결

- **Worldlines 계정**: 터미널에서는 `/login`, 웹에서는 로그인 버튼. 로그인하면 우리가 중계하는 모델을 쓰고, 판정자 **Jev**도 켜집니다.
- **내 키**: OpenCode, DeepSeek, OpenRouter, Anthropic, OpenAI, GLM, 또는 OpenAI 호환 엔드포인트.
- 새 판은 전에 고른 모델을 씁니다. 고른 적이 없고 로그인했다면 Worldlines를, 아니면 키가 있는 첫 번째 것을 씁니다.

**판정자**는 작은 예/아니오 질문에만 답합니다. 예를 들어 「이 상의는 정리됐나」, 「이 이름은 누구를 가리키나」 같은 것입니다. Jev가 없으면 **그 판의 모델**이 답합니다(박자마다 몇 초 더 걸림). 그것도 없으면 정해진 규칙으로 판정합니다. 판정자는 이야기를 쓰지 않습니다.

자세한 내용은 [모델 제공자 설정](/docs/players/providers)을 참고하세요.

<!-- section: start -->
## 3. 한 판 시작하기

템플릿을 고르고, (원하면) 내 캐릭터를 만들고, 시작을 누릅니다. 이때 엔진은 다음을 합니다.

1. `~/.worldlines/plays/` 아래에 새 폴더를 만듭니다. 이 판의 모든 것이 여기에 들어갑니다.
2. 템플릿의 세계, 고른 언어 층, 규칙 팩을 복사해 넣습니다.
3. **캐릭터는 이때 처음 실체화됩니다.** 템플릿의 캐릭터는 대부분 캐릭터 라이브러리로 가는 링크입니다. 시작할 때 비로소 이 판의 캐릭터로 복사되고, 자기 기억을 가집니다. 같은 캐릭터가 여러 세계에 동시에 살아도 서로 영향을 주지 않습니다.
4. 설정을 합칩니다: 규칙 팩 < 플레이 계약 < 편성 < 세계 < 이 판. 뒤의 것이 앞의 것을 덮어씁니다.
5. 오프닝을 재생하고(오프닝 이미지가 있으면 먼저 보여 줌), 진행자가 작가가 정한 첫 장면을 씁니다.

<!-- section: turn -->
## 4. 한 턴: 먼저 상의, 다음에 해결

당신이 한마디 하면 턴이 시작됩니다.

**상의 박자.** 진행자는 당신의 말을 장면에 놓고, 그 자리에 있는 캐릭터에게 마이크를 넘깁니다. 캐릭터는 대답하고, 조건을 걸고, 흥정합니다. 진행자는 이 일에 드는 돈, 거쳐야 할 판정, 걸리는 시간을 늘어놓습니다. **이 박자 동안 세계는 움직이지 않습니다.** 시계는 멈춰 있고 아무것도 바뀌지 않습니다. 계속 말해도 되고 마음을 바꿔도 됩니다.

상의에서 해결로 넘어가는 때:

- 판정자가 「정리됐다」고 판단할 때(Jev가 없으면 이 판의 모델이 판단);
- 당신이 직접 「결정」, 「그렇게 하자」라고 말할 때;
- 상의할 것이 없는 말(마을 안에서 몇 걸음 걷기 등)은 바로 해결로;
- 바깥 일은 상의가 끝나기를 기다려 주지 않습니다.

`@dm`은 진행자에게 과감하게 한 수 진행하게 합니다. `@이름`은 그 캐릭터에게 마이크를 넘깁니다.

**해결 박자.** 상의로 정한 일이 실제로 일어납니다.

1. **누가 움직이나.** 판정자가 당신이 하려는 일과 함께 움직일 캐릭터를 미리 읽습니다. 그 자리의 캐릭터는 각자 무엇을 할지 정하고, 자리에 없는 캐릭터도 다른 곳에서 한 걸음 나아갑니다.
2. **규칙이 먼저 판정.** 주사위가 필요하면 굴리고, 전투 같은 규칙 층이 필요하면 들어갑니다.
3. **서술 쓰기.** 진행자가 이 박자의 본문을 씁니다. 결과가 뒤의 전개에 영향을 주는 일이면 본문 안에서 도구를 한 번 부르고, 엔진이 그 자리에서 판정을 내리며, 진행자는 그 판정대로 이어서 씁니다. 상의로 정한 비용은 엔진이 지갑에서 바로 정산합니다.
4. **상태 쓰기.** 별도의 깨끗한 호출이 본문을 읽고 바뀐 것을 적습니다. 등록된 수치(돈, 체력, 시간…)와 세계 안의 파일(누가 어디로 갔는지, 무엇을 얻었는지)입니다.
5. **검사.** 엔진이 층마다 확인합니다. 형식이 맞는지, 이름과 변수가 있는지, 세계 규칙이 허락하는지. 틀리면 상태만 다시 쓰게 하고 본문은 그대로 둡니다.
6. **확정.** 변경을 파일에 쓰고, 턴 수를 1 올리고, 이 턴의 세계 커밋을 만듭니다.

**상태는 먼저 빠르게, 나중에 정확하게.** 4단계는 먼저 빠른 방식으로 확정되어 바로 이어서 플레이할 수 있습니다. 동시에 생각하는 느린 버전이 백그라운드에서 이 박자를 다시 읽고, 몇 초 뒤 잘못된 값을 고칩니다(최대 90초 대기). 화면에는 「다시 확인하는 중」이 나오고, 이어서 「고친 내용」이나 「변화 없음」이 나옵니다. 다음 말을 먼저 보내면 다시 확인은 취소됩니다.

<!-- section: save -->
## 5. 저장, 되돌리기, 리플레이

- 한 판은 폴더 하나이고, 한 턴에 커밋 하나입니다. 웹에서 커밋 그래프를 볼 수 있습니다.
- **되돌리기는 아무것도 지우지 않습니다**: 어떤 턴으로 돌아가면 거기서 새 줄기가 열리고, 원래 줄기도 남습니다. 터미널에서는 `/undo list`로 보고, `/undo <턴>`으로 돌아갑니다.
- `/save`, `/load`로 저장과 불러오기. `/open`으로 이어서 하거나 새 판을 시작합니다.
- 엔딩에서(또는 직접) **리플레이**로 내보낼 수 있습니다. 이야기, 타임라인, 표지를 묶어 다른 사람에게 보여 줄 수 있습니다.

자세한 내용은 [저장](/docs/players/saves)을 참고하세요.

## 6. 나만의 세계 만들기

길은 세 가지이고, 모두 같은 템플릿 폴더를 고칩니다.

- **웹 창작 데스크 / iOS**: 공식 템플릿에서 출발해 캐릭터, 플롯, 엔딩, 단서를 더하고, 4개 언어로 제목과 소개를 쓰고, 표지를 바꿉니다. 편성은 프리셋 2–3개 중에서 고르기만 하고, 그래프는 읽기 전용입니다.
- **로컬 워크벤치**: 「＋ 새 템플릿 / 세계 / 캐릭터」. 편성 그래프, 지도, 트리거를 고칠 수 있고, 고친 내용은 템플릿에 다시 저장됩니다.
- **coding agent**: Claude Code나 Codex로 템플릿 폴더를 엽니다. 모든 템플릿에 `AGENTS.md`, `CLAUDE.md`, `spec/`이 들어 있습니다. 스펙대로 폴더와 JSON / Markdown을 쓰면 되고, 엔진을 고칠 필요는 없습니다.

캐릭터는 캐릭터 라이브러리(`~/.worldlines/souls/`)에 두고, 템플릿에는 링크만 씁니다.

자세한 내용은 [크리에이터 빠른 시작](/docs/creators/quickstart)을 참고하세요.

<!-- section: lint -->
## 7. 검사(lint)

`neonrp template lint <템플릿>` 또는 워크벤치의 검사는 먼저 템플릿을 임시 폴더에 한 판으로 열어 본 다음, 참조, 캐릭터, 플롯, 소재, 플레이 계약, 4개 언어를 검사합니다. 결과는 두 단계입니다. **block**은 공개를 막고, **warn**은 알림만 합니다.

<!-- section: publish -->
## 8. Hub에 공개하기

| | 올리는 방법 | 볼 수 있는 사람 |
|---|---|---|
| **자유 구역** | 로컬 창작 데스크에서 바로 업로드. 자동 검사를 통과하면 바로 공개 | 모두. 관리는 나중에 |
| **기본 구역** | 웹 / iOS 창작 데스크에서 제출하고 심사로 | 심사를 통과하면 게시 |

업로드 전 관문은 세 가지입니다. 패키지에 키나 인증 정보 파일이 없을 것. lint에 block이 없을 것. 4개 언어의 제목과 소개, 표지가 다 갖춰져 있을 것. 같은 작품을 다시 제출하면 새 버전이 됩니다. 심사 중에 다시 제출하면 대기 중이던 버전을 대신합니다. 게시된 작품을 고친 경우, 새 버전이 심사를 통과할 때까지 공개된 것은 이전 버전 그대로입니다.
