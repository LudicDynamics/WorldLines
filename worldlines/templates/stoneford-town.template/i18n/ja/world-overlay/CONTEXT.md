# この世界のコンテキスト言語(エンジンが生成。手で直さないこと。manifest.json の prompt を変えたら再生成する)

## エンジンが毎ターンモデルに見せるもの(語彙パック)
順に:時刻 · 町 / 現在地 / 出口 · この町の場所 id · 居合わせたキャラと NPC · プレイヤー · 人物設定(居合わせたキャラ) · よそにいるキャラ · 世界メモ / 噂 / 背景 · 登録済みクラス · エンジンからの通知 · 変数と変数ルール · 直近の語り。
続いてユーザーブロック:ツールの返答 · キャラの返答 · 関連エントリ(ヒットしたもの) · プレイヤーの今の行動 · (却下された時)前回の提案。

## モデルが書くもの(出力形式)
## 出力形式
次のフォーマットを厳守する。ブロックの外には何も書かない。
lines:画面に順番に表示されるメッセージ。キャラクターのセリフは必ず「」で囲む(書き出しは「、末尾は」)。「」で囲まれていないメッセージは地の文として扱う。セリフと地の文を同じメッセージに書かないこと。ADVのテキストパネルに表示するものなので一文一行。
ops:このターンの状態変化を一行に一つ。変化がなければ 変化なし と一行だけ書く。書ける行:
move <誰> <どこへ>           移動:誰 = player か居合わせたキャラ / NPC の名前、どこへ = この町の場所 id、または新しい地名(地図になければその場で作る)。このターンの最終到達地を書く。通過地は書かない。町内ならどこでも一ターンで着く
[ask <誰>]                要求:居合わせたキャラの返答を待ってから続きを書く。一ターンに二つまで
player.hp -3          変数:名前 + 数値。+ / − 付きは増減、なしは設定
flag <フラグ>               ストーリーフラグ
new_location <名前> <親> <隣接> 新しい場所(writer):new_location <名前> に地図のどの層かを一つ添える——near=<A>[,<B>] 同じ層で隣;between=<A>,<B> 二か所の間の道;in=<A> A の中(一つ下の層、A からしか出入りしない);over=<A>,<B> 同じ層の数か所を包む(一つ上の層、街区など)。分からなければ書かない——プレイヤーの隣に置き、ターン後に描写から置き直す
link <a> <b>             新しい道:link <場所A> <場所B>(同じ町でまだ繋がっていない二か所。近道を見つけた時など)
unlink <a> <b>           道が断たれる:unlink <場所A> <場所B>(橋が落ちた、道が塞がれた。町のどこかに行けなくなるなら不可)
new_town <名前> <from> <days> <summary> <tags> 新しい町(writer):世界地図にまだない町へ向かう時、世界がその場で町を生やす——new_town <名前> from=<道の起点の町> days=<道中の日数> summary=<一行> tags=<道の状態、カンマ区切り>;その後ふつうに旅する
new_npc <名前> <場所> <役>    新しい通行人(writer)
new <クラス> <名前>           登録済みクラスの新しいインスタンス(語彙パックに「登録できるクラス」がある時だけ)
patch <誰> <属性>           オープンスキーマ:人・物・場所のどれにでも属性を書く——patch <名前> 属性=値 …。新しい属性はそのまま足され、その対象自身の記録に書き込まれる(宣言済みの属性は変更可能なものだけ。名前・id・位置は変えられない——誰かをどこかへ行かせるなら move)
remove <誰>               オープンスキーマ:インスタンスが世界から消える(使い切った、役目を終えた)——remove <名前>
write <path>             ファイル:世界フォルダの .json / .md / .txt を新規作成・上書き——[~write パス]内容[/write](JSON は正しく)
edit <path>              ファイル:JSON のキーを設定——edit <パス> キー=値 …
rm <path>                ファイル:削除——rm <パス>(遊びの中で作ったものだけ)
mkdir <path>             フォルダ:作成——mkdir <パス>
rmdir <path>             フォルダ:遊びの中で作ったものを削除——rmdir <パス>
define <kind> <名前>       オープンスキーマ:世界にまだない種類のものが要る時はその場で定義——define class <クラス名> <見出し> 属性=型 …(int/str/bool/list、選択肢は a|b|c)mutable=変更可能な属性,…(effect=yes:毎ターン効く状態);define var <名前> <型> <初期値> min= max=。定義後すぐ new / patch / remove / 変数書き込みに使える
[roll <ダイス>]             要求:ダイスは 1d6 / 2d10 / 2d6+1 の形。出目を自分で作らない
[dice <ダイス> <vs>]        判定:[dice 1d20+2 vs 12]何を何故判定するか[/dice]。出目と成否はエンジンが返す
[~map]                   地図:[~map] エンジンが実状態から現在地の文字地図(町 / 地下 / 街道)をプレイヤーに直接表示。返答は待たず続きを書く。自分で地図を描かない
[~sheet]                 キャラシート:[~sheet] エンジンが能力・持ち物・財布をパネルで直接表示。返答は待たない。数値を本文に書かない
[referee <question>]     審判要求:[referee プレイヤーの試み]。規則と能力から裁定が返る。裁定どおりに書く
[combat …]…[/combat]     戦闘層へ:[combat 山賊×5 隻眼の虎×1]なぜ始まるか[/combat]。タグ内の 名前×数 が相手の名簿(エンジンが生成)、本文は引き継ぎ。lines はそこで止まり、戦闘審判が続ける
end_combat <outcome>     戦闘層専用:end_combat outcome=won|fled|lost
trade <good> <qty>       プレイヤーが町の市場で売り買いする(trade grain 3。数量をマイナスにすると 85 % の値で売る)
new_caravan <from> <どこへ> <good> <qty> 世界ルール:値差が十分に開くと隊商が出発する(エンジンが自動で行う。語りの中でこの op を直接書かない)
haul <cv>                世界ルール:隊商が一区間進む
deliver <cv>             世界ルール:隊商が荷を届ける
rob <cv>                 世界ルール:隊商が襲われる
[~show <slot>]           表示:[~show <素材>] テンプレートの絵を今この瞬間全画面で見せる(物語の挿絵・段階の場面転換)。下に挙げたものだけ。返答は待たない。表示できるもの:N201 ミロ
変化なし
options:この返答を受けてプレイヤーが言いそうなセリフ・行動を2〜4個。短く(20文字以内)、方向性をばらけさせる(友好的/挑発的/話題を変える など)。一選択肢一行。
行動は lines の中に直接書いてもよく、ops の一行と同じ意味になる:[~move player inn]あなたは宿の扉を押し開けた。、または [~flag paid]。角括弧の要求を書いた行で lines は止める。エンジンの返答を受けてから続きを書く。エンジンからの通知は山括弧で届く:<event>/<end> は起きたこと、<say> はキャラの発言、<roll 1d6>4</roll> は要求への返答、<refused> は却下の理由。

EXAMPLE OUTPUT:
<lines>
あなたはリバーランプ亭の扉を押し開けた。炉の熱が頬に触れる。
「一部屋。二人だ」
ミラがカウンターの奥から顔を上げ、二人をひと眺めした。
「一晩八枚、前払いでね」
エレナは何も言わず、外套の滴を払った。
</lines>
<ops>
move player inn
move エレナ inn
player.gold -8
</ops>
<options>
「一晩分だけ払う」
ミラにローワンを見なかったか聞く
「高すぎる」
踵を返して出る
</options>

## コンテキスト言語:括弧の形 = 返答を待つかどうか
- `[tag args]` 同期の要求:その行で lines を止め、エンジンの返答を受けてから続きを書く(例 `[dice 1d20+2 vs 12]理由[/dice]`、`[referee プレイヤーの試み]`、`[ask エレナ]`、`[combat 山賊×3]引き継ぎ[/combat]`)
- `[~tag args]` 非同期の動作:返答は待たない。エンジンがそのまま実行し、モデルは書き続ける(例 `[~move player inn]`、`[~flag paid]`、`[~player.gold -3]`、`[~map]`)。ops の一行と同じ意味
- 待つかどうかはエンジンの登録表が決める(各 op が wait を宣言している)。モデルの括弧が間違っていても登録表どおりに実行し、食い違いは trace に記録する
- 旧形式 `<move player inn>` も読める。`[~move player inn]` と同じ扱い
エンジンからモデルへの通知は山括弧:`<event ルールid>起きたこと</event>` · `<end エンディングid>結びのヒント</end>` · `<say 名前 attitude=…>セリフ</say>` · `<roll 1d6>4</roll>` · `<refused op 項目>理由;選べるもの:…</refused>`。

## エントリ(manifest.json → "prompt" → "entries"。プレイ中の変更は game/meta/prompt.json)
- `"when": "always"` はシステムプロンプトに入る。`"post"` は最後に置く。条件つきのもの(`{"keyword": …}` · `{"at": …}` · `{"var": …, ">=": n}` · `{"flag": …}`)は、条件を満たした時に「プレイヤーの今の行動」の直前に差し込まれる。
- `rules` / `voice` / `blocks` / `ops_docs` もここで変える。三層構造:テンプレートの pack.json < manifest.json < game/meta/prompt.json。
