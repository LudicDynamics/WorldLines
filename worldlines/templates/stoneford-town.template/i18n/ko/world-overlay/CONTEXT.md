# 이 세계의 컨텍스트 언어(엔진이 생성함, 손으로 고치지 말 것 — manifest.json → prompt를 바꾼 뒤 다시 생성)

## 엔진이 매 턴 모델에게 보여 주는 것(팩)
순서대로: 시간 · 마을 / 여기 / 출구 · 이 마을의 장소 id · 그 자리의 캐릭터와 NPC · 플레이어 · 인물 설정(그 자리의 캐릭터) · 다른 곳에 있는 캐릭터 · 세계 메모 / 소문 / 배경 · 등록된 클래스 · 엔진 메시지 · 변수와 그 규칙 · 최근 서술.
그다음 사용자 블록: 도구 결과 · 캐릭터들의 대답 · 관련 항목(걸린 항목) · 지금 플레이어 · (거절 시) 지난 제안.

## 모델이 쓰는 것(출력 형식)
## 출력 형식
아래 형식을 정확히 지켜 출력한다. 블록 밖에는 아무것도 쓰지 않는다.
lines: 화면에 순서대로 표시되는 메시지. 캐릭터의 대사는 반드시 큰따옴표로 감싼다("로 시작해서 "로 끝난다). 따옴표가 없는 메시지는 지문으로 본다. 대사와 지문을 한 메시지에 섞어 쓰지 않는다. ADV 텍스트 패널에 표시될 내용이므로 한 줄에 한 문장.
ops: 이번 턴의 상태 변화, 한 줄에 하나; 아무것도 바뀌지 않았으면 한 줄만: 변화 없음. 쓸 수 있는 줄:
move <누가> <어디로>          이동: 누가 = player 또는 그 자리에 있는 캐릭터 / NPC의 이름, 어디로 = 이 마을의 장소 id, 또는 새 장소 이름(지도에 없으면 그 자리에서 만들어진다). 이번 턴에 최종적으로 도착한 곳만 쓰고 지나친 곳은 쓰지 않는다. 마을 안이라면 어디든 한 턴에 갈 수 있다
[ask <누가>]               요청: 그 자리의 캐릭터가 먼저 대답해야 이어 쓸 수 있을 때. 한 턴에 최대 두 번
player.hp -3          변수: 이름 + 숫자; 앞에 + / − 가 붙으면 증감, 없으면 설정
flag <플래그>               story flag
new_location <이름> <상위> <인접> 새 장소(writer): new_location <이름> 뒤에 지도의 어느 층에 놓일지 관계를 하나 붙인다 — near=<A>[,<B>] 같은 층에서 나란히; between=<A>,<B> 두 곳 사이의 길 위; in=<A> A의 안쪽(한 층 아래, A로만 드나듦); over=<A>,<B> 같은 층의 여러 곳을 감싸는 위층(예: 한 구역). 애매하면 쓰지 않는다 — 엔진이 일단 플레이어 옆에 걸어 두고, 턴이 끝난 뒤 서술을 보고 제자리에 놓는다
link <a> <b>             길 잇기: link <장소A> <장소B>(같은 마을에서 원래 이어지지 않던 두 곳, 예를 들어 지름길을 찾았을 때)
unlink <a> <b>           길 끊기: unlink <장소A> <장소B>(다리가 무너지거나 길이 막혔을 때; 끊으면 마을 일부로 갈 수 없게 되는 경우는 거절된다)
new_town <이름> <from> <days> <summary> <tags> 새 마을(writer): 플레이어가 세계 지도에 아직 없는 마을로 가려 할 때 세계가 그 자리에서 자라난다 — new_town <이름> from=<길이 시작되는 마을> days=<길에서 보낼 날수> summary=<한 줄 설명> tags=<길 상태, 쉼표로 구분>; 그다음 평소처럼 길을 떠난다
new_npc <이름> <어디서> <역할>  새 행인(writer)
new <클래스> <이름>           오픈 schema: 등록된 클래스의 인스턴스를 새로 만든다. new <클래스> <이름> 속성=값 … 으로 쓴다(어떤 클래스와 속성이 있는지는 팩의 '등록 가능한 클래스' 참고)
patch <누가> <속성>          오픈 schema: 사람 / 물건 / 장소 누구에게든 속성을 쓴다. patch <이름> 속성=값 … 으로 쓴다. 새 속성은 그대로 추가되어 그 대상의 기록에 남는다(선언된 속성은 바꿀 수 있는 것만; 이름, id, 위치는 못 바꾼다 — 자리를 옮기려면 move)
remove <누가>              오픈 schema: 인스턴스 하나가 세계에서 사라진다(다 써 버렸거나 끝났을 때). remove <이름> 으로 쓴다
write <path>             파일: 세계 폴더 안의 .json / .md / .txt 파일을 새로 만들거나 덮어쓴다. [~write 경로]내용[/write] 으로 쓴다(JSON은 파싱돼야 함; 경로는 세계 폴더 기준, '세계 폴더' 참고)
edit <path>              파일: JSON 파일의 키를 고친다. edit <경로> 키=값 … 으로 쓴다(점으로 중첩을 나타내며, 새 키는 그대로 추가)
rm <path>                파일: 파일을 지운다. rm <경로> 로 쓴다(플레이 중에 쓴 것이나 오픈 schema 폴더 안의 것만)
mkdir <path>             폴더: 새 폴더를 만든다. mkdir <경로> 로 쓴다
rmdir <path>             폴더: 플레이 중에 만든 폴더를 안의 파일째 지운다. rmdir <경로> 로 쓴다
define <kind> <이름>       오픈 schema: 세계에 아직 없는 종류의 것이 필요할 때 그 자리에서 정의한다 — define class <클래스명> <제목> 속성=타입 …(타입 int/str/bool/list, 선택지는 a|b|c) mutable=바꿀 수 있는 속성,…(effect=yes: 턴마다 효과가 도는 상태); define var <이름> <타입> <초기값> min= max=. 정의한 뒤 바로 new / patch / remove / 변수 쓰기를 할 수 있다
[roll <주사위>]             요청: 주사위를 굴린다. 1d6 / 2d10 / 2d6+1 처럼 쓰고, 눈을 직접 지어내지 않는다
[dice <주사위> <vs>]        판정: [dice 1d20+2 vs 12]무엇을 왜 판정하는지[/dice]; 엔진이 눈과 성공 / 실패를 돌려준다. 이유는 네가 쓰고, 눈은 엔진이 낸다
[~map]                   지도: [~map] 엔진이 실제 상태대로 지금 위치의 문자 지도(마을 안 / 던전 / 길 위)를 그려 플레이어에게 바로 보여 준다. 답을 기다리지 않으니 lines는 계속 쓴다. 지도를 직접 그리지 않는다
[~sheet]                 캐릭터 시트: [~sheet] 엔진이 플레이어의 능력치 / 소지품 / 지갑을 패널로 그려 바로 보여 준다. 답을 기다리지 않는다. 서술 속에서 수치를 읽어 주지 않는다
[referee <question>]     심판 요청: [referee 플레이어가 하려는 불확실하거나 무리한 일]; 규칙 심판이 규칙과 캐릭터 시트를 보고 판정(가능한지, 판정이 필요한지, 결과)을 내리면 너는 그 판정대로 쓴다
[combat …]…[/combat]     전투 층으로 전환: [combat 산적×5 외눈 호랑이×1]왜 싸움이 붙었는지[/combat]; 태그 안의 이름×수가 상대 명단이고(엔진이 표대로 만든다), 본문은 인계하는 말이다. lines는 이 줄에서 멈추고 전투 심판 층이 이어 쓴다(선제 / 명중 / 피해는 모두 [dice])
end_combat <outcome>     전투 층 전용: end_combat outcome=won|fled|lost 로 전투 층을 떠난다
변화 없음
options: 플레이어가 이 대목을 듣고 할 만한 말이나 행동 2~4개. 짧게(20자 이내), 방향이 서로 다르게(우호 / 도발 / 화제 전환 등). 한 줄에 하나.
행동은 lines 안에 바로 적어도 되고, ops 한 줄과 같은 효과다: [~move player inn]여관 문을 밀고 들어간다., 또는 [~flag paid]. 대괄호 요청을 쓰면 lines는 그 줄에서 멈추고, 엔진이 답한 뒤 이어서 쓴다. 엔진은 꺾쇠괄호로 답한다: <event>/<end>는 이미 일어난 일, <say>는 캐릭터가 한 말, <roll 1d6>4</roll>는 요청에 대한 답, <refused>는 거절된 이유.

출력 예시:
<lines>
리버램프 여관 문을 밀자 화롯불의 온기가 얼굴에 닿는다.
"방 하나요, 둘이 쓸 겁니다."
미라가 카운터 너머에서 고개를 들어 너희를 한번 훑어본다.
"하룻밤에 여덟 닢. 선불이에요."
엘레나는 말없이 망토에 묻은 물기를 털어 낸다.
</lines>
<ops>
move player inn
move 엘레나 inn
player.gold -8
</ops>
<options>
"하룻밤 값부터 낼게요"
미라에게 로완을 본 적 있는지 묻는다
"너무 비싼데요"
돌아서서 나간다
</options>

## 컨텍스트 언어: 괄호 모양 = 답을 기다리는지
- `[태그 인자]` 동기 요청: lines는 그 줄에서 멈추고, 엔진이 답한 뒤 이어 쓴다(예: `[dice 1d20+2 vs 12]이유[/dice]`, `[referee 플레이어가 하려는 일]`, `[ask 엘레나]`, `[combat 산적×3]인계[/combat]`)
- `[~태그 인자]` 비동기 행동: 기다리지 않고 엔진이 그대로 실행하며 모델은 계속 쓴다(예: `[~move player inn]`, `[~flag paid]`, `[~player.gold -3]`, `[~map]`); ops 한 줄과 같다
- 기다릴지 말지는 엔진의 등록표가 정한다(op마다 wait를 선언); 모델이 괄호를 잘못 써도 등록표대로 실행되고, 어긋남은 trace에 기록된다
- 옛 형식 `<move player inn>`도 여전히 인식되며 `[~move player inn]`과 같다
엔진은 꺾쇠괄호로 모델에게 알린다: `<event 규칙id>이미 일어난 일</event>` · `<end 결말id>에필로그 힌트</end>` · `<say 이름 attitude=…>대사</say>` · `<roll 1d6>4</roll>` · `<refused op 필드>이유; 가능: …</refused>`.

[combat …]…[/combat]     전투 층으로 전환: [combat 산적×5 외눈 호랑이×1]왜 싸움이 붙었는지[/combat]; 태그 안의 이름×수가 상대 명단이고(엔진이 표대로 만든다), 본문은 인계하는 말이다. lines는 이 줄에서 멈추고 전투 심판 층이 이어 쓴다(선제 / 명중 / 피해는 모두 [dice])
end_combat <outcome>     전투 층 전용: end_combat outcome=won|fled|lost 로 전투 층을 떠난다

## 항목(manifest.json → "prompt" → "entries"; 플레이 중 변경은 game/meta/prompt.json)
- `"when": "always"`는 시스템 프롬프트에 들어가고 `"post"`는 맨 끝에 붙는다; 조건부 항목(`{"keyword": …}` · `{"at": …}` · `{"var": …, ">=": n}` · `{"flag": …}`)은 조건이 맞으면 '지금 플레이어' 앞에 붙는다.
- `rules` / `voice` / `blocks` / `ops_docs`도 여기서 고친다. 세 층: 템플릿 pack.json < manifest.json < game/meta/prompt.json.
